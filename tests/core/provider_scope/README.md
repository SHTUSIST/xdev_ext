# Independent DMA scoped-window acceptance

The oracle is the separately frozen provider-scope contract and assertion document. These tests do not use old fault tests or implementation-authored expectations. The comparator cohort executes the actual pure helper; the lifecycle cohort includes complete production DMA C and substitutes kernel primitives and the public mechanism/provider boundary only.

`run.py --mode legacy-adapter` uses a signature-only bridge into the real old overlap function. It intentionally fails the new distinct-scope capability while retaining same-provider legacy numeric controls. It is not a candidate implementation or candidate acceptance adapter.

`run_lifecycle.py --mode legacy-control` compiles and executes the real old registry/bind/lease/completion/unbind path. `--mode candidate` requires the new production pure header and real scope symbols; absence is SETUP. It never supplies a scope implementation. All candidate scenarios run in separate processes so deliberately quarantined bindings are not force-freed to make subsequent tests pass.

The kernel boundary represents allocation, lists, mutexes, refcounts, module pins, plain provider ABI structures and mechanism session/batch services. A new native invocation receives a new ticket while retaining its batch/slot generation. It does not implement register, scope lifetime, DMA lease, bind/unbind, overlap, serial or quarantine algorithms. Scope objects remain opaque; their references are observed through real public operations, callback effects and module pin balances.

This host build does not prove physical mapping honesty, actual kernel object layout, interrupt races, real module unloading or native DMA qualification. Root's existing real-kernel short→independent-open, alias, UNKNOWN/mixed and module-pin cases remain required. No extra virtual device or native fixture is introduced.

Run commands and immutable evidence live under the dedicated staging dma-scope-tests directory. Root owns manifests, CI and final test-results registration.
