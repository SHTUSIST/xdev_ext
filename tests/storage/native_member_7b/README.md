# Native member 7B host characterization

This independent cohort compiles complete selected production functions and headers against controlled external kernel API boundaries. The common family algorithms and registered native member hooks execute in the assembled host translation unit. Expected command, PDU and coherent-list bytes remain frozen literals.

Python 3 and GCC are required. From the canonical product checkout, run:

```sh
python3 tests/storage/native_member_7b/verify.py --source-root "$PWD" --out "$PWD/build/native-member-7b-ci"
```

The output directory must not exist. Select a fresh owned output path for each run. The entry runs strict, bounce and disabled configurations, original golden GCC and UBSan cohorts, common ownership checks and custom callback byte checks, followed by all 54 compiled semantic, wiring and callback-consumer mutants. A kill requires compile exit zero, run exit one and the designated literal assertion diagnostic. Compile/setup errors and unrelated runtime failures fail the entry.

Six sibling `../native_member_7a` files are reused byte-for-byte. The shared `boundary.h` adds only the BIO iterator OS members required by the selected production interface; its original members, boundary behavior and numeric assertions remain unchanged. All seven files are reused directly without duplication. `INPUTS.json` pins public test input hashes, including this explicit OS declaration revision; it does not pin production source to one historical commit. `SOURCE.json` and `SOURCE-AFTER.json` record the explicitly selected canonical source root, selected source hashes and executing public test input hashes. Before/after mismatch fails the entry. Future valid production sources can be tested without replacing an old source-SHA gate.

`assemble.py` retains complete selected production definitions. This cohort covers opened namespace files: the existing explicit namespace-file boundary projects the separate window-handle region, while the actual namespace lookup, native bind, requester selection and class bind remain intact. Real requester types, admission, bind/unbind and shared command-builder dependencies are assembled with recorded external provider/PCI facts. Missing CREATE preparation remains a real failure; the boundary does not supply a successful requester. `adapter.py` changes only fixture access paths to actual common owners, trusted slot strides and initializer namespace metadata, and records the expanded source inventory. It records every positional field/fixture edit and reverses it exactly. The entry requires exactly fourteen records: six original assertion transforms, six extended assertion transforms and two golden candidate transforms, with the expected labels and original input hashes. `PROOFS.json` retains their before/after edits and exact-reversal evidence. Literal assertion sources, byte oracles, original mutation definitions and custom callback checks remain unchanged. The recipe observes the actual initializer's entry/exit; it does not replace its body.

`RESULT.json` records strict acceptance checks and subprocess exits. Raw compiler/runtime logs, generated C, copied includes, selected commands, per-mutant recipes and reversal records remain beneath the output directory. The six expected diagnostics are golden558 twice, strict600, bounce671, disabled599 and common82 plus custom34; the entry checks their exact text as well as exits. Missing, duplicate, extra or relabelled cohort/mutant/reversal rows fail acceptance. All 12 original 7A mutation IDs and designated assertions remain required on their actual 7B owners, together with the initial 45 7B recipes; three IDs overlap, yielding 54 unique cases. The shared golden assertions and existing 7A entry remain unchanged.

This is host correctness evidence at actual production function/header boundaries. Kernel object/module builds, native kernel execution, actual DMA, performance, a second real storage member and later storage slices require separate acceptance.
