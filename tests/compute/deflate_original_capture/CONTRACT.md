# Frozen original-capture requirements (pre-execution)

Input: exactly4096 bytes; for index i=0..4095, block=i/64, lane=i%64, byte=((lane*13+7) XOR ((block%7)*29)) AND255. It is independent of production source. Preserve input.bin and its entire hex encoding. Do not predict or synthesize compressed bytes.

Layout: frame_size8192, headroom128, segment4096, group4096, six frames, depth1, one START batch lending only frame0. Initial complete pool byte is0x97, with the fixed input at frame0+128. Compressor capacity8192 spans two reserved frames; inflater capacity4096 spans one distinct reserved frame. CPU destination windows come from current CREATE reservation and are observed rather than hard-coded. IAA compressor first output frame1 and inflater first output frame3. CPU arg0 DEFLATE/INFLATE, arg1 capacities8192/4096; IAA SOFTWARE flag, TO/FROM directions, arg0 first frame and arg1 capacities. CPU direction always TO_DEVICE and fd=-1. IAA uses an ordinary eventfd only as its existing file lifetime token; it performs no I/O on it. USER delta0 and deadline60000ms; two distinct handles.

CPU allocation is unchanged crypto_alloc_acomp("deflate-generic",0,CRYPTO_ALG_ASYNC); IAA SOFTWARE allocation is unchanged crypto_alloc_acomp("deflate-generic",0,0), with MAY_BACKLOG callback flags. Parameters are the exact frozen upstream deflate defaults; no compression tuning is exposed by these stage ABIs. Root preserves the selected upstream implementation and /proc/crypto stanza. A /proc/crypto registration is qualification evidence, not a new per-request driver query.

The output observer uses existing USER UAPI acquire/release ordering and ticket checks. It copies the entire produced spans and lengths while USER holds them and preserves each full compressed frame before completing that USER stage. It writes no payload. Then the real same-class INFLATE receives exactly those descriptors/lengths. The second USER observes exact4096-byte reconstruction, compares every byte to the independent input, and checks original source frame0 plus all compressed-source frame bytes. Entire pool outside the admitted compression/inflation capacity spans must still equal the initial pool; all output frame headroom/tails, unused frames and source headroom/tail are checked.

Only all of: exact input; two nonempty compressed byte artifacts; both exact reconstructions; source/guard checks; all four stages submitted/completed once; done1/abort0/reject0/protocol0/timeout0/sequestered0/inflight0/last_err0; successful STOP; and final CPU/IAA byte-equality observation earns the final PASS. Equality is observed and reported; unequal valid encodings are not automatically a failure. The original compressed bytes remain authoritative separately for each class.

Any absent class/crypto provider/BTF, attach/CREATE/START error, timeout, no output, failed reconstruction, source/guard mutation, unexpected counter or failed artifact write exits nonzero. No SKIP-as-PASS, user-space zlib compressor, CryptoAPI stub, DMA simulation, added device/provider or performance timing. Wait bounds serve correctness termination only.

Root must record actual source identity and verify kernel/source compatibility independently; this author's source-only freeze is not native correctness evidence. Root retains full logs and all bytes even on failure and registers successful evidence under test-results/correctness/linux-kvm-and-driver-validation-on-6787p, with relative evidence links and catalog checks.

## Retry2 failure evidence contract (before implementation)

The fixed input, four-stage semantics, capacities, native methods and all success checks above remain binding. USER is included by CONFIG_XDEV_EXT_MECH; no separate nonexistent USER Kconfig line is required. Live USER BTF/attach/USER_STAGE/CREATE/START remain fatal if unsupported.

Every successfully observed actual compressor/inflater byte buffer is emitted before payload/source/guard assertions. Even a failed or incomplete capture yields durable diagnostic extraction: all unambiguous well-formed actual BYTES records are retained, actual retained lengths are recorded, and errors/missing success markers/reconstruction mismatches/explicit native failure or nonzero capture/guest exits force a nonzero extractor status. No later PASS clears an earlier failure. Such result.json is DIAGNOSTIC_FAILURE with diagnostic/errors truthy, valid_original=false, and source_of_compressed_expectations='diagnostic only; not a valid original'. It cannot release COMP-4 or supply a golden.

On a failing case, before cleanup, bounded actual pool/snapshot frame bytes are emitted using BYTES names diag.CLASS.pool.fN, diag.CLASS.initial.fN and diag.CLASS.compressed_snapshot.fN, where CLASS is cpu or iaa, N=0..5 and each record contains exactly8192 bytes. Initial/snapshot namespaces are emitted only after their respective actual memcpy initialization. At most18 such records are emitted per case. These remain diagnostics even if their byte record syntax is valid; they never count among the five required successful original records. A conflicting duplicate name has no unambiguous authoritative artifact; the receipt names the ambiguity and preserves every other valid record. Reader memory/line processing is bounded and does not read the whole log at once.

## Retry3 retained-state bound

CASE state is only two fixed bits (cpu/iaa). Any unknown/malformed CASE creates a permanent fixed-category error; neither its identifier nor its line enters a retained collection or message. Final-marker state saturates at2, where0 means absent,1 exactly one and2 multiple. error_count saturates at65535; additional errors set error_count_overflow=true. errors retains only the first128 bounded messages, and error_messages_omitted explicitly indicates further omitted messages. Error state never returns to zero. Existing BYTES/ambiguous/retained names remain the same41 fixed names with at most8192 bytes each; zero-exit state remains two fixed strings. The reader streams to EOF using the existing bounded line/chunk reads, with no arbitrary total-file/time cutoff. All accepted unambiguous observations still persist on diagnostic failure and cannot become valid originals after a later PASS.

## Retry4 CASE status classification

For a CASE marker, the third whitespace-separated token is the status and must equal uppercase PASS exactly; the prior whole-word-space guard also remains required. Only the existing cpu/iaa identifiers can set their success bits. Missing or non-PASS statuses create the existing fixed-category malformed-CASE error; unknown names create a fixed-category error as well. PASS appearing later in the body cannot qualify a FAIL, PASSIVE, lowercase or other status. A later valid CASE/final PASS never clears an earlier error. This clarifies the existing malformed-marker requirement only; it adds no body-field specification or native format change, and all retry3 state bounds, EOF streaming and diagnostic retention continue unchanged.
